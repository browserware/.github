## Affected Pages/Routes

- CLI command `brw contexts` — verify table, JSON, and plain output for browser contexts.
- Library API `browserware-types` — verify `BrowserContext`, `ProfileRef`, `LaunchCapability`, and `ContextSelector` serialize, deserialize, and match deterministically.
- Library API `browserware-profiles` — verify profile discovery from deterministic fixtures, not live machine state.

## Key Interactions to Verify

- A developer runs `brw contexts --format json` and receives parseable JSON with browser, profile, selector, and capability fields.
- A developer runs `brw contexts` and sees a human-readable table with copyable canonical selectors.
- A script runs `brw contexts --format plain` and receives stable script-friendly identifiers or selectors.
- Selector matching handles exact matches and ambiguous matches according to policy: first, warn, or error.

## Edge Cases

- Chrome-family fixtures with multiple profile directories and profile display names.
- Firefox `profiles.ini` fixtures with multiple profiles and missing or malformed sections.
- Browsers with no profile support, such as default-only Safari-style contexts.
- Inaccessible, encrypted, malformed, or unknown profile metadata returns capability limitations instead of panicking or silently omitting contexts.
- Empty/no-context discovery exits successfully with a clear message.
- Ambiguous selectors produce deterministic behavior under each configured ambiguity policy.

## Firefox Note

- Current Firefox discovery only reads `Name=` entries from `profiles.ini`.
- `Path=` and `IsRelative=` are not used yet, so relative-path and absolute-path fixtures are not distinct behavior in this milestone.
- If path-aware Firefox profile resolution is added later, add dedicated fixtures and tests for relative and absolute path handling then.

## Critical Paths

- `detect_browsers()` output is transformed into `BrowserContext` rows without losing unknown browsers.
- Profile discovery enriches contexts where metadata is available and emits default/limited contexts where it is not.
- `brw contexts --format json` remains stable enough for automation and agent workflows.
- Capability flags are present for every context: `discoverable`, `launchable`, `profile_launchable`, `requires_user_config`, and `limitations`.
